# Elizabeth — Luxury Villa Collection

Многостраничный сайт-каталог агентства недвижимости: виллы Пхукета в сегменте **$1–2M**,
продажа и длительная аренда. Сайт собран как presale-инструмент — квалифицировать посетителя,
снять страхи по сделке в чужой юрисдикции и довести до заявки.

---

## Запуск

```bash
npm install
npm run dev          # http://localhost:3000
```

```bash
npm run build && npm start   # продакшн-сборка
```

Требуется Node.js 20+. Внешних сервисов, ключей и переменных окружения нет — шрифты лежат
локально, бэкенда на этом этапе нет.

## Публикация на GitHub Pages

Сайт статический, поэтому публикуется целиком, включая фильтры (они работают в браузере).
Деплой автоматический: пуш в рабочую ветку → сборка → публикация.

**Разовая настройка:** в репозитории `Settings` → `Pages` → в поле *Source* выбрать
**GitHub Actions**. Больше ничего включать не нужно.

Адрес сайта: `https://<владелец>.github.io/<репозиторий>/`

Сборкой занимается `.github/workflows/deploy-pages.yml`. Две переменные окружения
включают режим статики:

| Переменная | Значение | Зачем |
|---|---|---|
| `STATIC_EXPORT` | `true` | собрать статику в `out/` вместо обычной сборки |
| `NEXT_PUBLIC_BASE_PATH` | `/elizabeth` | сайт живёт в подпапке, а не в корне домена |

Обычные `npm run dev` и `npm run build` эти переменные не выставляют, поэтому локальная
разработка идёт как раньше — без подпапки в адресе.

Проверить сборку для Pages локально:

```bash
STATIC_EXPORT=true NEXT_PUBLIC_BASE_PATH=/elizabeth npm run build
```

Готовые файлы окажутся в `out/`. Учтите: открывать их напрямую из файловой системы
бесполезно — нужен веб-сервер, отдающий сайт из подпапки `/elizabeth`.

**Если репозиторий переименуют**, поменяйте `/elizabeth` в двух местах
`deploy-pages.yml` — в переменной `NEXT_PUBLIC_BASE_PATH` и в шаге правки путей
к шрифтам. Имя ветки для запуска тоже задаётся там, в блоке `on: push:`.

**Про шрифты.** Они подключены в CSS абсолютным путём `/fonts/...`. В подпапке такой
путь ведёт мимо, поэтому workflow отдельным шагом дописывает префикс в собранном CSS.
Исходники при этом не меняются. Если добавите новые шрифты — префикс проставится сам,
шаг ищет все `.css` в `out/`.

## Стек

| Что | Чем | Почему |
|---|---|---|
| Фреймворк | Next.js 16, App Router | отдельный URL на каждую страницу каталога и каждую карточку — нужно для SEO и шаринга ссылок |
| Стили | Tailwind CSS v4 (CSS-first `@theme`) | токены темы живут в CSS, без `tailwind.config.js` |
| Язык | TypeScript, strict | типизированная модель данных виллы |
| Данные | локальные TS-файлы | мок-слой, заменяемый на CMS без правок вёрстки |
| Шрифты | локальные woff2 в `public/fonts` | нет зависимости от Google CDN, работает офлайн |

Все страницы, кроме фильтров каталога и формы, — серверные компоненты и пререндерятся статикой
(24 маршрута на сборке).

## Структура сайта

| URL | Страница | Задача страницы |
|---|---|---|
| `/` | Главная | развилка по задаче посетителя: жить / инвестировать / арендовать перед покупкой |
| `/villas` | Каталог | фильтры: гео-кластер, тип сделки, бюджет, спальни, статус, задача |
| `/villas/[id]` | Карточка объекта | фото, планировка, структура владения, что проверили, что не так, что рядом |
| `/areas` | Гео-кластеры | список районов с блоком «кому не подходит» |
| `/areas/[slug]` | Район | инфраструктура, трафик в сезон, сезонность, объекты кластера |
| `/rent-to-buy` | Аренда → покупка | страница-мост: зачем сначала прожить сезон |
| `/legal` | Юридический гид | leasehold / freehold / компания, миф «30+30+30», Hotel Act, чек-лист до задатка |
| `/about` | Об агентстве | сделки по кластерам, форма due diligence, чем отличаемся, чего не делаем |
| `/contact` | Заявка | форма с квалификацией: задача, бюджет, сроки, районы |

Фильтры каталога живут в query-параметрах (`/villas?deal=rent&cluster=Layan`), поэтому ссылку на
отфильтрованную подборку можно переслать, а кнопка «назад» работает предсказуемо.

## Где менять данные

Вся фактура вынесена из вёрстки в три файла. Компоненты не знают, откуда пришли данные.

### `src/data/villas.ts` — объекты

Массив `villas: Villa[]`. Тип `Villa` описывает карточку целиком: цена, кластер, тип сделки,
структура владения, статус, площади, фото, «что рядом», due diligence, честный минус объекта и
задачи, под которые объект подходит.

**Подключение CMS:** замените массив на запрос к источнику, сохранив тип `Villa` —
вёрстка не изменится:

```ts
// было
export const villas: Villa[] = [ /* ... */ ];

// стало
export async function getVillas(): Promise<Villa[]> {
  const res = await fetch(process.env.CMS_URL!, { next: { revalidate: 300 } });
  return res.json();
}
```
После этого страницы, которые импортируют `villas`, переводятся на `await getVillas()`
(они уже серверные, `async` добавляется без других правок). `generateStaticParams`
в `src/app/villas/[id]/page.tsx` тоже станет `async`.

Поля, на которые стоит обратить внимание при заполнении:

- `pricePeriod` — `"total"` для продажи, `"month"` для аренды. От него зависит и формат цены,
  и то, какие бюджетные полосы покажет фильтр.
- `rentalLicensed` — есть ли у проекта гостиничная лицензия. Ставьте `true` **только** при
  наличии документа: от этого флага зависит, обсуждает ли сайт краткосрочную доходность.
- `tradeoff` — честный минус объекта. Обязательное поле: оно выводится на карточке выше
  достоинств и является основным элементом доверия.
- `dueDiligence` — что проверено. Если по объекту нечего написать, объект не должен попадать
  в каталог.

### `src/data/clusters.ts` — гео-кластеры

Массив `clusters: ClusterInfo[]`. Тексты районов, инфраструктура, трафик, сезонность и
обязательный блок `notFor` («кому не подходит»).

`clusterSlugByName` связывает название кластера в карточке виллы со slug страницы района —
при добавлении нового кластера дополните эту карту, иначе с карточки не будет ссылки на район.

### `src/data/agency.ts` — цифры и процедуры агентства

Метрики, гео-компетенции, шаги due diligence, отличия, контакты, дисклеймер.

> **Все числовые показатели помечены `sample: true` и выводятся с видимой плашкой «Пример».**
> Перед публикацией замените их фактическими данными из CRM и снимите флаг. Константа
> `PLACEHOLDER` (`[ПРИМЕР — заменить реальными данными]`) используется там, где цифры пока нет.

Контакты (WhatsApp, Telegram, email, адрес) тоже здесь — они подтягиваются в шапку, подвал,
форму и страницу контактов из одного места.

## Форма заявки

Форма (`src/components/QualifyForm.tsx`) собирает квалификацию: задача (переезд / доход /
второй дом / сезон перед покупкой), тип сделки, бюджет, сроки, районы, комментарий. С карточки
объекта передаётся `?villa=<id>` и подставляется в заявку.

Отправка изолирована в **одной функции** — `src/lib/submitLead.ts`:

```ts
export async function submitLead(lead: Lead): Promise<SubmitResult>
```

Сейчас она открывает почтовый клиент через `mailto` с уже отформатированным письмом. Чтобы
подключить настоящий обработчик, замените тело функции на запрос — состояния формы
(отправка / успех / ошибка), валидация и вёрстка менять не нужно:

```ts
const res = await fetch("/api/lead", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(lead),
});
if (!res.ok) return { ok: false, error: "Не удалось отправить. Напишите в WhatsApp." };
return { ok: true };
```

Тип `Lead` и функция `formatLead()` (человекочитаемое письмо для менеджера) уже готовы —
их можно переиспользовать в route handler'е для отправки в CRM, Telegram-бота или на почту.

## Фотографии

Реальной съёмки нет — вместо неё компонент `src/components/Photo.tsx` рисует плейсхолдер
в фирменных тонах с подписью, **что именно должно встать в этот кадр** (подписи лежат в
`imageCaptions` каждой виллы).

Замена на реальные фото:

1. Положите изображения в `public/photos/<villa-id>/<name>.webp`.
2. В `Photo.tsx` замените тело компонента на `next/image`:

```tsx
import Image from "next/image";

<Image
  src={`/photos/${villaId}/${name}.webp`}
  alt={caption}
  fill
  sizes="(max-width: 640px) 100vw, 33vw"
  className="object-cover"
/>
```

Разметка карточек, галереи и страниц районов при этом не меняется — все они получают фото
через тот же компонент.

## Дизайн-система

Токены — в `src/app/globals.css`, блок `@theme`. В компонентах сырые hex не используются.

**Палитра** (снята с фирменного борда):

| Роль | Токен | Значение |
|---|---|---|
| Тёмный слой, шапки секций | `olive-900 / olive-800` | `#232b1d` / `#2e3826` |
| Бумага сайта | `cream-50 / cream-100` | `#faf8f0` / `#f4f1e2` |
| Единственный акцент | `gold-500 / gold-600` | `#c9a24c` / `#ac863a` |
| Второстепенный текст | `ink-soft / ink-muted` | `#4c5347` / `#6d7268` |
| Сигнал «лицензия есть» | `emerald-signal` | `#0f8f52` — больше нигде не используется |

**Шрифты** — три роли, все локальные:

| Роль | Гарнитура | Замена чему |
|---|---|---|
| Заголовки | **Prata** | Didot |
| Акцентная строка курсивом | **Cormorant Garamond Italic** | — |
| Подпись бренда (латиница) | **Pinyon Script** | Snell Roundhand |
| Интерфейс и текст | **Jost** | — |

> Важное ограничение: сайт русскоязычный, поэтому рабочие гарнитуры обязаны иметь кириллицу.
> Bodoni Moda (ближайший веб-аналог Didot) кириллицы **не содержит** — заголовки молча
> уезжали бы в Georgia, поэтому взят Prata, тоже дидон и с кириллицей. Pinyon Script кириллицы
> тоже не имеет, поэтому применяется **только** к латинской подписи `Luxury Villa Collection`;
> для русских акцентных строк есть утилита `.accent` (курсив Cormorant Garamond).

Шрифты скачаны из Google Fonts (лицензия OFL) и подключены через `src/app/fonts.css`.
Чтобы обновить набор, скачайте нужные woff2 в `public/fonts` и допишите `@font-face`.

## Контентные правила, зашитые в проект

Они важнее вёрстки — если их нарушить, сайт перестаёт отличаться от двадцати других.

1. **Никаких цифр доходности без раскрытой модели.** Блок «Экономика владения» на карточке
   показывает *структуру* расчёта, а не результат; все незаполненные значения помечены
   `[ПРИМЕР — заменить реальными данными]`.
2. **«30+30+30 = 90 лет владения» не пишем.** Это договорное обещание, а не срок владения;
   разбор — на `/legal`.
3. **Краткосрочная аренда — только с лицензией.** Сдача менее чем на 30 дней подпадает под
   Hotel Act. Флаг `rentalLicensed` управляет тем, что сайт говорит инвестору.
4. **У каждого объекта и каждого района есть минус.** Поля `tradeoff` и `notFor` обязательны.
5. **Один объект — разные аргументы.** Блок «Что смотреть именно вам» на карточке разворачивает
   объект под задачу из `fitsJobs`, а не даёт универсальный текст.
6. **Примерные данные помечены визуально**, а не сноской в подвале.

## Проверено

- Сборка проходит, 24 маршрута пререндерятся статикой.
- Адаптив снят на 390 / 768 / 1024 / 1440 px, горизонтального скролла нет.
- Клавиатурная навигация: видимый фокус не снят нигде, есть ссылка «К основному содержанию».
- Тач-цели в фильтрах и форме — от 44 px, ошибки формы выводятся рядом с полем.
- `prefers-reduced-motion` отключает анимации и плавный скролл.

## Что не сделано намеренно

- Бэкенда, базы и CRM нет — заявка уходит через `mailto` (см. «Форма заявки»).
- Реальной фотосъёмки нет — плейсхолдеры с подписями.
- Мультиязычности нет: сайт русскоязычный. Для английской версии — `next-intl` и вынос текстов
  из компонентов в словари; тексты для сегментов не переводятся дословно, аргументы разные.
